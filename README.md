# SportStore

SportStore — учебный проект интернет-магазина, разработанный на Django в рамках курса по веб-разработке.

## Возможности

- Главная страница со списком товаров
- Постраничный вывод товаров
- Страница с подробной информацией о товаре
- Фильтрация товаров по категориям
- Кеширование страницы товара
- Низкоуровневое кеширование списка товаров категории с использованием Redis
- Регистрация и авторизация пользователей
- Личный профиль пользователя
- Загрузка изображений товаров
- Страница контактов
- Bootstrap 5
- Маршрутизация Django
- Шаблоны с наследованием
- PostgreSQL
- Django ORM
- Полный CRUD для товаров
- Создание и редактирование товаров через формы Django
- Удаление товаров
- Валидация названий и описаний товаров по списку запрещённых слов
- Валидация цены товара
- Блог

## Технологии

- Python 3.13
- Django 6
- PostgreSQL
- Poetry
- Bootstrap 5
- Pillow
- psycopg2-binary
- redis

## Структура каталога

Основное приложение проекта — `catalog`.

В приложении реализованы:

- модель `Category` — категории товаров;
- модель `Product` — товары;
- связь товаров с категориями через `ForeignKey`;
- загрузка тестовых данных через JSON-фикстуры;
- кастомная команда для загрузки фикстур;
- настройка моделей в Django Admin;
- сервис для получения товаров определённой категории;
- кеширование списка товаров категории.

Приложение users отвечает за работу с пользователями:

- кастомная модель пользователя;
- регистрация и авторизация;
- профиль пользователя;
- аватар пользователя;
- дополнительные данные пользователя.

Приложение blog используется для работы с публикациями блога.

## Кеширование
Для кеширования используется Redis.
Redis настроен как backend кеширования Django и работает в отдельной базе Redis.
Для страницы подробной информации о товаре используется кеширование на 300 секунд.
Список товаров выбранной категории кешируется с использованием ключа:
category_{id}
Время хранения данных в кеше — 300 секунд.
Для локального запуска Redis используется Docker-контейнер.

## Переменные окружения

Для работы проекта необходимо создать файл `.env` в корневой директории проекта.

Пример необходимых переменных находится в файле `.env.example`.

В `.env` указываются:

- `SECRET_KEY` — секретный ключ Django;
- `DATABASE_NAME` — название базы данных PostgreSQL;
- `DATABASE_USER` — пользователь PostgreSQL;
- `DATABASE_PASSWORD` — пароль пользователя PostgreSQL;
- `DATABASE_HOST` — адрес сервера PostgreSQL;
- `DATABASE_PORT` — порт PostgreSQL.

Файл `.env` не должен добавляться в репозиторий.

## Запуск проекта

Установить зависимости:

```bash
poetry install
```
Выполнить миграции:

```bash
poetry run python manage.py migrate
```
Запустить Redis:

```bash
docker start redis-local
```

Запустить сервер:

```bash
poetry run python manage.py runserver
```

После запуска проект доступен по адресу:

http://127.0.0.1:8000/

## Загрузка тестовых данных

Для загрузки тестовых категорий и продуктов используются фикстуры:

```bash
poetry run python manage.py loaddata catalog/fixtures/categories.json
poetry run python manage.py loaddata catalog/fixtures/products.json
```

Также реализована кастомная команда, которая предварительно очищает существующие данные и загружает фикстуры:

```bash
poetry run python manage.py load_fixtures
```

## Административная панель

Для работы с товарами и категориями используется Django Admin:

http://127.0.0.1:8000/admin/

Для доступа необходимо создать суперпользователя:

```bash
poetry run python manage.py createsuperuser
```

## Валидация форм

Формы создания и редактирования товаров используют `django.forms`.

Реализована валидация:

- проверка названия и описания на наличие запрещённых слов без учёта регистра;
- проверка цены — цена не может быть отрицательной;
- проверка загружаемого изображения по формату и размеру.

Запрещённые слова:

- казино;
- криптовалюта;
- крипта;
- биржа;
- дешево;
- бесплатно;
- обман;
- полиция;
- радар.
